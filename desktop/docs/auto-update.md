# Windows 자동 업데이트 운영 — 2026-11-12

## 현재 상태

기준은 저장소 desktop/입니다. 현재 소스는 v0.1.2이며, 기존 0.1.1의 GitHub 업데이트 경로와 고정 설치 파일명을 유지합니다. 0.1.2의 실제 Windows 빌드·설치·업데이트·데이터 보존은 [검증 실행 43167661283](https://github.com/psho0324/-/actions/runs/43167661283)에서 통과했습니다. 공개 완료 상태와 파일은 [최신 Release](https://github.com/psho0324/-/releases/latest)에서 확인합니다.

## 이후 버전 배포 기준

2026-11-12 사용자는 이후 수정·추가에 따른 새 버전을 앱의 자동 업데이트로 받아 확인하는 방식을 요청했습니다. 앱 변경과 버전 업데이트를 요청한 작업은 검증 후 같은 배포 경로로 공개하며, 통상적인 버전 배포에 대해 별도 확인을 반복 요청하지 않습니다. 사용자가 검토만 요청하거나 배포 보류를 명시하면 그 요청을 우선합니다.

- 앱 버전과 잠금 파일 버전을 함께 올립니다. 기존 공개 태그를 덮어쓰지 않고 새 버전 태그를 사용합니다.
- Windows 빌드·설치·실제 업데이트·데이터 보존 및 화면 검사가 모두 통과해야 일반(stable) Release를 공개합니다. 실패하면 기존 최신 Release와 다운로드 경로를 유지합니다.
- 같은 빌드의 설치 파일·latest.yml·blockmap·체크섬을 함께 공개합니다. 다른 앱의 파일을 이 업데이트 경로에 섞지 않습니다.
- 새 버전 자동 확인·다운로드 후 설정의 ‘설치하고 다시 시작’으로 적용합니다. 저장·백업 확인을 건너뛰거나 일반 종료 시 몰래 설치하는 동작은 추가하지 않습니다.
- 홈페이지 버전 표시는 실제 Release 파일이 공개된 뒤 갱신합니다. 버전 문자열 변경만으로 배포·설치 완료를 주장하지 않습니다.

공개 0.1.0에는 updater가 없으므로 0.1.1 설치 파일은 한 번 직접 설치해야 합니다. 0.1.1에서 이후 버전을 확인하는 경로를 준비했습니다.

## 동작과 변경 이유

설치된 Windows NSIS 앱만 시작 10초 뒤와 6시간 간격으로 공개 GitHub Releases를 확인합니다. 개발 실행·브라우저·Microsoft Store 패키지는 대상에서 제외합니다. Store용은 Store 업데이트를 사용해야 합니다.

정식 최신 버전을 자동 다운로드하지만 설치는 설정의 ‘설치하고 다시 시작’ 버튼으로만 진행합니다. `autoInstallOnAppQuit=false`로 일반 종료·OS 종료를 설치 계기로 삼지 않습니다. 사용자 동의 후 화면 저장 완료 응답이 정확히 true인지 확인하고 store.backupNow()가 성공해야 `quitAndInstall(true,true)`를 호출합니다. 저장 실패·응답 지연·백업 실패·종료 중에는 설치하지 않습니다. 다운로드 준비 시 설정 메뉴에 표시합니다.

새 모듈 updater.js는 상태·중복 실행·오류 처리를 담당합니다. main.js는 기존 저장 확인과 백업에 연결하고, preload.js는 고정 IPC만 노출합니다. renderer는 상태와 버튼을 표시합니다. 이후 전체 감사에서 store.js의 백업·복구·파일 읽기 처리를 보완했으며 데이터 스키마는 유지했습니다. 기존 userData와 backups 위치를 유지합니다. 저장소 안정성 보완 내역은 [전체 감사](../../AUDIT-2026-11-11.md)에 기록했습니다. 계정·일정·키를 업데이트 서버에 올리는 기능은 없습니다.

설치 실행 실패 뒤에는 라이브러리 내부 상태 때문에 같은 실행에서 재시도하지 않고 앱을 다시 실행하도록 안내합니다. 프로세스 종료 후 설치 실패에 대한 자동 롤백은 구현하지 않았습니다. 이 경우 수동 재실행·공개 설치 파일 재설치가 필요할 수 있습니다.

## 패키징과 배포

운영 의존성 electron-updater 6.8.11을 잠금 파일에 고정했습니다. 생성된 app-update.yml의 GitHub provider는 owner psho0324, repo -입니다. 설치 파일 이름은 MyPlanner-Setup.exe로 유지합니다. 사용자 다운로드 고정 주소:

https://github.com/psho0324/-/releases/latest/download/MyPlanner-Setup.exe

업데이트에는 설치 파일만이 아니라 같은 빌드에서 생성한 latest.yml과 생성 시 MyPlanner-Setup.exe.blockmap을 함께 공개해야 합니다. 메타데이터 버전·파일 이름·SHA-512·크기를 실제 설치 파일과 검사합니다. 태그는 package 버전과 일치해야 하며, Windows 검사 실패 시 Release 단계가 실행되지 않습니다.

서명 검증을 끄는 코드는 추가하지 않았습니다. 현재 미서명 앱이므로 SmartScreen 경고는 남습니다. 향후 서명 도입 시 게시자 이름과 인증서를 일관되게 설정하고 실제 Windows 갱신 경로를 다시 검증해야 합니다.

## 실제 검증과 미확인 범위

- 최신 전체 감사에서는 Node 테스트 원본 5개·업데이트 2개·실행 안전성 1개 파일이 통과했습니다. 제어 검사 18개는 저장/타임아웃/백업 실패 차단과 실제 main.js의 설치 순서를 가짜 Electron으로 검증합니다.
- 실제 electron-updater/NSIS 다운로드 코드로 로컬 HTTP 파일을 내려받아 정상 해시 허용·틀린 해시 거부·하위 버전 거부 3개 통과. 파일은 가짜 바이트이며 실행하지 않습니다. 외부 GitHub와 실제 설치 검증을 대신하지 않습니다.
- Linux 실제 Electron 45.3.0 검사 13개 그룹과 Chromium 화면 검사 176개 통과. 사용자 프로필 대신 임시 가짜 데이터만 사용했습니다.
- Windows용 ASAR 생성과 코드·운영 의존성·생성된 업데이트 설정의 검사는 로컬에서 수행합니다. 전체 NSIS 제작은 이 Linux 환경에 Wine이 없어 `spawn wine ENOENT`로 중단됐습니다. 이후 실제 Windows CI에서 설치·다음 패치 갱신 검사를 통과했습니다.

Windows 워크플로에는 원본 버전을 무인 설치한 뒤 다음 패치 버전을 임시로 빌드하는 실제 갱신 검사를 추가했습니다. 새 CI 전용 프로필만 허용하고 실제 저장 실패를 일으켜 설치 차단을 검사한 뒤 복구하여 설치·재실행·버전·두 가짜 할 일·로컬 백업을 확인합니다. 임시 설치본만 로컬 feed를 사용하고, 공개할 원본 설치 파일과 package/lock을 복원 후 재검사합니다. 임시 다음 버전을 공개하지 않습니다. 이 검사는 커밋 524ae94의 Windows CI에서 통과했습니다. Release 작업은 skipped였으며 공개 배포하지 않았습니다.

기존 미확인 수동 항목: 트레이 모양/메뉴, 실제 알림 표시/클릭, Windows 로그인 자동 시작, 실제 OneDrive 등, 복원 화면, 읽기 전용 폴더의 종료 안내. 사용자 데이터나 비밀 키는 검사·커밋·Release에 포함하지 않습니다.

## 배포 전 확인

Windows 검사와 실제 설치 업데이트 검사 결과를 확인하고, 설치 파일·메타데이터·검사 기록이 같은 버전인지 확인합니다. 검증한 변경을 main에 반영하고 package 버전과 일치하는 새 태그로 공개합니다. 사용자가 명시한 배포 보류가 있으면 진행하지 않습니다. 소스 버전 표시만으로 새 버전이 사용자 PC에 설치됐다고 판단하지 않습니다.
