# Windows 자동 업데이트 — 2026-11-11 갱신

## 현재 상태

기준은 저장소 desktop/이며 예전 ZIP을 덮어쓰지 않았습니다. 소스와 최신 Windows 테스트 Release는 v0.1.1입니다. 사용자의 배포 요청으로 검증한 수정본을 main과 공개 다운로드에 반영했습니다. 배포된 main은 `f2f3810`, v0.1.1 태그는 `1784918`입니다. [공개 재검증 42968618404](https://github.com/psho0324/-/actions/runs/42968618404)에서 Windows 설치/갱신/재실행/데이터 보존과 Release 공개가 성공했습니다. [main 검사 42969480142](https://github.com/psho0324/-/actions/runs/42969480142)도 성공했습니다. 이전 [실행 42936674499](https://github.com/psho0324/-/actions/runs/42936674499)는 배포 전 검증 기록입니다.

공개 0.1.0에는 updater가 없으므로 0.1.1 설치 파일은 한 번 직접 설치해야 합니다. 0.1.1에서 이후 버전을 확인하는 경로를 준비했습니다.

## 동작과 변경 이유

설치된 Windows NSIS 앱만 시작 10초 뒤와 6시간 간격으로 공개 GitHub Releases를 확인합니다. 개발 실행·브라우저·Microsoft Store 패키지는 대상에서 제외합니다. Store용은 Store 업데이트를 사용해야 합니다.

정식 최신 버전을 자동 다운로드하지만 설치는 설정의 ‘설치하고 다시 시작’ 버튼으로만 진행합니다. `autoInstallOnAppQuit=false`로 일반 종료·OS 종료를 설치 계기로 삼지 않습니다. 사용자 동의 후 화면 저장 완료 응답이 정확히 true인지 확인하고 store.backupNow()가 성공해야 `quitAndInstall(true,true)`를 호출합니다. 저장 실패·응답 지연·백업 실패·종료 중에는 설치하지 않습니다. 다운로드 준비 시 설정 메뉴에 표시합니다.

새 모듈 updater.js는 상태·중복 실행·오류 처리를 담당합니다. main.js는 기존 저장 확인과 백업에 연결하고, preload.js는 고정 IPC만 노출합니다. renderer는 상태와 버튼을 표시합니다. 이후 전체 감사에서 store.js의 백업·복구·파일 읽기 처리를 보완했으며 데이터 스키마는 유지했습니다. 기존 userData와 backups 위치를 유지합니다. 저장소 안정성 보완 내역은 [전체 감사](../../AUDIT-2026-11-11.md)에 기록했습니다. 계정·일정·키를 업데이트 서버에 올리는 기능은 없습니다.

설치 실행 실패 뒤에는 라이브러리 내부 상태 때문에 같은 실행에서 재시도하지 않고 앱을 다시 실행하도록 안내합니다. 프로세스 종료 후 설치 실패에 대한 자동 롤백은 구현하지 않았습니다. 이 경우 수동 재실행·공개 설치 파일 재설치가 필요할 수 있습니다.

## 패키징과 배포

운영 의존성 electron-updater 6.8.11을 잠금 파일에 고정했습니다. 생성된 app-update.yml의 GitHub provider는 owner psho0324, repo -입니다. 설치 파일 이름은 MyPlanner-Setup.exe로 유지합니다. 사용자 다운로드 고정 주소:

https://github.com/psho0324/-/releases/latest/download/MyPlanner-Setup.exe

업데이트에는 설치 파일만이 아니라 같은 빌드에서 생성한 latest.yml과 생성 시 MyPlanner-Setup.exe.blockmap을 함께 공개해야 합니다. 메타데이터 버전·파일 이름·SHA-512·크기를 실제 설치 파일과 검사합니다. 태그는 package 버전과 일치해야 하며, Windows 검사 실패 시 Release 단계가 실행되지 않습니다.

서명 검증을 끄는 코드는 추가하지 않았습니다. 현재 미서명 앱이므로 SmartScreen 경고는 남습니다. 향후 서명 도입 시 게시자 이름과 인증서를 일관되게 설정하고 실제 Windows 갱신 경로를 다시 검증해야 합니다.

## 실제 검증과 미확인 범위

**실제 GitHub provider를 거치는 업데이트 경로는 다음 실제 공개 버전에서 처음 확인해야 합니다.** 현재 운영 설정은 GitHub provider(`owner: psho0324`, `repo: -`)이지만 지금까지의 실제 설치·갱신 검사는 로컬 서버의 generic provider로 수행했습니다. v0.1.1 Release의 파일 목록·해시 확인은 별도 확인이며, v0.1.1 앱이 GitHub의 다음 공개 버전을 받아 설치했다는 증거를 대신하지 않습니다. 검사에서 만든 다음 패치 버전은 공개하지 않았습니다.

- 최신 전체 감사에서는 Node 테스트 원본 5개·업데이트 2개·실행 안전성 1개 파일이 통과했습니다. 제어 검사 18개는 저장/타임아웃/백업 실패 차단과 실제 main.js의 설치 순서를 가짜 Electron으로 검증합니다.
- 실제 electron-updater/NSIS 다운로드 코드로 로컬 HTTP 파일을 내려받아 정상 해시 허용·틀린 해시 거부·하위 버전 거부 3개 통과. 파일은 가짜 바이트이며 실행하지 않습니다. 외부 GitHub와 실제 설치 검증을 대신하지 않습니다.
- Linux 실제 Electron 45.3.0 검사 13개 그룹과 Chromium 화면 검사 176개 통과. 사용자 프로필 대신 임시 가짜 데이터만 사용했습니다.
- Windows용 ASAR 생성과 코드·운영 의존성·생성된 업데이트 설정의 검사는 로컬에서 수행합니다. 전체 NSIS 제작은 이 Linux 환경에 Wine이 없어 `spawn wine ENOENT`로 중단됐습니다. 이후 실제 Windows CI에서 설치·다음 패치 갱신 검사를 통과했습니다.

Windows 워크플로에는 원본 버전을 무인 설치한 뒤 다음 패치 버전을 임시로 빌드하는 실제 갱신 검사를 추가했습니다. 새 CI 전용 프로필만 허용하고 실제 저장 실패를 일으켜 설치 차단을 검사한 뒤 복구하여 설치·재실행·버전·두 가짜 할 일·로컬 백업을 확인합니다. 임시 설치본만 로컬 feed를 사용하고, 공개할 원본 설치 파일과 package/lock을 복원 후 재검사합니다. 임시 다음 버전을 공개하지 않습니다. 이 검사는 커밋 524ae94의 Windows CI에서 통과했습니다. Release 작업은 skipped였으며 공개 배포하지 않았습니다.

기존 미확인 수동 항목: 트레이 모양/메뉴, 실제 알림 표시/클릭, Windows 로그인 자동 시작, 실제 OneDrive 등, 복원 화면, 읽기 전용 폴더의 종료 안내. 사용자 데이터나 비밀 키는 검사·커밋·Release에 포함하지 않습니다.

## 2026-11-11 배포 확인과 다음 공개 버전 검증

v0.1.1의 태그·Release·main 반영·홈페이지 배포는 이미 완료됐습니다. 첫 태그 검사 실패 후 태그의 앱 본체와 동일함을 검사하는 재검증을 거쳐 공개했습니다. 공개 설치 파일의 SHA-256·SHA-512와 Windows 검사 기록을 확인한 결과는 [전체 감사 갱신](../../AUDIT-2026-11-11.md)에 구분합니다.

다음 공개 버전은 사용자의 배포 지시가 있을 때만 준비합니다. 버전이 올라간 실제 GitHub Release를 만들고, 기존 v0.1.1 설치 앱이 GitHub provider에서 해당 메타데이터와 설치 파일을 받아 저장·백업·갱신·재실행까지 성공하는지 처음 확인해야 합니다. 이를 확인하기 위해 이번 검토 중 v0.1.2를 임의 공개하지 않습니다.

## 미배포 후속 검토 브랜치

새 버전 다운로드 완료 알림은 버전당 한 번 제공하도록 보완합니다. 알림 설정이 꺼져 있거나 OS 알림을 지원하지 않으면 알림을 생략하고 버전을 알림 완료로 기록하지 않습니다. OS 알림의 `show` 이벤트가 발생한 뒤에만 userData의 별도 `planner-update-notices.json`에 버전 목록을 기록해 재실행 사이의 중복도 막습니다. 일정·사용자 설정 JSON의 형식과 저장 위치는 유지하며 이 보조 파일에는 일정이나 비밀번호를 넣지 않습니다. 보조 기록 쓰기가 실패하면 앱을 중단하지 않고 해당 실행의 메모리 상태로 중복을 줄입니다. 실제 OS에 알림이 표시됐는지는 Windows 수동 확인이 필요합니다. ready 상태의 트레이 항목은 기존 `updates.install()`을 사용해 저장과 백업 확인을 그대로 거칩니다.

`fix/planner-review-followup` 변경은 현재 공개된 v0.1.1과 별개입니다. 저장 실패 중 강제 복원/기본 위치 전환은 미저장 자료와 원본 백업을 함께 보존한다고 보장하기 어려워 차단을 유지하는 방식을 선택했습니다. 먼저 화면에서 백업 내보내기로 현재 내용을 보관하고, 저장 권한·폴더 상태를 복구한 뒤 ‘다시 시도’로 저장을 확인하도록 안내합니다. 저장 확인 없이 업데이트를 설치하거나 일반 종료에 자동 설치하는 동작은 추가하지 않습니다.

일반 설치 앱 smoke 검사는 실제 GitHub의 최신 Release와 네트워크 상태에 영향을 받지 않도록 `CI=true`와 `PLANNER_DISABLE_AUTO_UPDATE=1`을 자식 앱에 함께 설정해 정기 확인 시작만 생략합니다. updater 자체는 활성 상태이며 수동 확인·설치 API와 ‘설치 앱에서 unsupported가 아님’ 검사는 유지합니다. 실제 사용자의 일반 실행은 이 테스트 조건에 해당하지 않아 기존 자동 확인 동작을 유지합니다. 실제 다운로드·설치 검사는 격리된 로컬 generic provider로 따로 실행합니다. 이 브랜치의 새 동작과 검사 결과는 실제 검증이 끝난 뒤 보고하며, 기존 공개 버전의 통과 기록으로 대신하지 않습니다.

로컬 generic E2E의 최초 자식 앱에도 같은 CI 변수를 전달하고 수동 확인·설치 경로로 검사합니다. 정기 확인 타이머 자체는 별도 제어 검사로 구분합니다. NSIS가 다시 실행한 프로세스의 환경 상속 여부를 독립적으로 계측한 것은 아니며, 일반 smoke의 GitHub 요청 0건 검사와 혼동하지 않습니다.
