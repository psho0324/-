## 배포 승인 규칙

**모든 배포는 사용자가 확인하고 승인한 뒤에만 진행한다.** 검사 결과와 변경 내용·미확인 항목을 먼저 보여 주고, 사용자가 명시적으로 **“배포해”**라고 말한 뒤에만 진행합니다. 검사 통과와 수정 요청은 배포 승인이 아닙니다.

승인 전 금지 항목은 main 병합, 앱 버전 올리기, 태그 푸시, Release 공개, 홈페이지 다운로드 버전 변경입니다. 이번 후속 수정과 0.1.3 배포도 예외가 아닙니다. 자동 업데이트로 편하게 받겠다는 이전 요청을 승인 없는 배포의 근거로 해석했던 문구는 제거했습니다.

## 앱 수정안에 포함된 내용

- `main.js`: 업데이트 다운로드가 준비되면 버전당 한 번 OS 알림을 요청합니다. 실제 표시 성공 후 별도 내부 파일에 기록하며, 알림 설정과 OS 지원 여부를 존중합니다. 알림 클릭은 앱을 엽니다. 트레이에 ‘새 버전 설치하고 다시 시작’을 추가하고 기존 저장·백업 확인 경로로 연결합니다.
- `main.js`: 시작 실패를 일정 파일 손상, 저장 위치 설정 손상, 기타 실패로 구분하여 원본·백업 위치와 복구 방법을 안내합니다. 원본 일정이나 설정을 삭제하지 않습니다.
- `main.js`, `renderer/app.js`: 백업·복원·저장 위치 변경 실패 시 저장 재시도, 폴더 권한, 내보내기 등 사용자가 할 수 있는 조치를 구체적으로 안내합니다.
- `renderer/index.html`, `renderer/styles.css`: 설정의 선택·스위치·버전 표시가 좁은 화면에서 제목과 나란히 유지되도록 정리합니다. 0.1.2의 테마 선택도 보존합니다.
- `.gitattributes`: Windows 배치 파일의 줄바꿈을 CRLF로 고정합니다.
- `package.json`, `package-lock.json`: 테스트 목록에 릴리스 파일 검사를 추가하고 검사 도구에서 직접 사용하는 기존 의존성을 명시합니다. 앱 버전은 올리지 않습니다.
- `.github/workflows/desktop.yml`, `tools/verify-release-assets.cjs`: Electron 설치 명령과 실제 공개 목록의 필수 파일 누락 검사를 준비합니다. 이 목록 검사는 공개 후 확인 단계이며 자동 롤백 기능은 아닙니다. 이번에 워크플로를 실행하거나 파일을 공개하지 않았습니다.

`store.js`, `preload.js`, 반복 목표 계산·저장 형식, 공휴일 자료는 이번에 변경하지 않았습니다. 공휴일 자동 갱신도 구현하지 않았습니다. 개인 일정·인증 정보는 사용하지 않았습니다.

## 남은 사항

1. 이번 수정안을 실제 Windows에서 빌드·설치·갱신하는 검사가 남아 있습니다. 트레이 외관·클릭, OS 알림 외관·클릭, 다음 로그인 자동 시작, 실제 OneDrive, 복원 화면과 읽기 전용 폴더 종료 안내는 사용자 PC의 수동 확인도 필요합니다.
2. 공개 0.1.2 자체에는 새 준비 완료 알림 코드가 없습니다. 수정된 다음 버전을 받는 동안에는 기존 앱의 설정에서 확인해야 하며, 새 알림은 수정된 앱을 설치한 뒤 그다음 업데이트부터 작동합니다.
3. 0.1.1로 되돌린 뒤 저장하면 0.1.2의 실천·못함 기록이 제거될 수 있습니다. 복구·다운그레이드 전 백업이 필요하며 이번 작업에서 자동 롤백을 추가하지 않았습니다.
4. 목표 삭제 후 남는 못함 기록은 이번에 임의 삭제하지 않았습니다. 현재 사용자 화면의 오류로 재현되지 않은 낮은 우선순위 데이터 정리 사항입니다.
5. 홈페이지 코드의 `tests/`와 실제 운영 Supabase는 이번 앱 후속 검토에서 다시 검사하지 않았습니다. SETUP과 과거 감사 문서의 이관 안내는 문서 변경이며 운영 DB를 실행·수정한 것이 아닙니다.

검사 결과와 위 변경을 사용자에게 먼저 보고합니다. 승인 전에는 버전 변경·main 병합·태그·Release·홈페이지 다운로드 변경을 진행하지 않습니다.
