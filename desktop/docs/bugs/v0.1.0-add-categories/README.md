# v0.1.0 할 일·목표 추가 / 카테고리 관리 신고

기록일: 2026-11-10. 사용자가 Codex와 Claude에게 함께 공유한 문제입니다. **관찰 기록을 먼저 공유하고 앱 코드 변경 내용·이유를 사전에 알린다**는 기존 규칙을 따릅니다. 이 기록은 앱 수정·문제 해결 완료 선언이 아닙니다.

## 환경과 사용자 신고

- 사용자 앱: 기존에 배포한 `v0.1.0`으로 확인. Windows 세부 버전·빌드는 미확인으로 남깁니다. 추가 자료 제출을 전제로 진행하지 않습니다.
- 신고 1: 할 일·목표의 ‘추가’를 눌러도 아무 반응이 없음. 할 일은 캘린더·빠른 추가로 넣을 수 있지만 목표 추가 경로가 막힘.
- 신고 2: 기존/새 카테고리의 이름 변경·삭제를 찾을 수 없어 카테고리만 늘어남.
- 조사 기준: 저장소 `desktop/`, 앱 코드가 ZIP 전달본과 같은 `v0.1.0`. 이번에 앱·테스트·빌드·SQL을 변경하지 않았습니다.
- 직접 검사 환경: Linux Debian 13, 실제 Electron `33.4.11`, 앱 버전 `0.1.0`. 가짜 일정만 사용한 격리 프로필로 실행하고 종료 후 프로필을 지웠습니다. Windows의 사용자 환경 전체를 재현했다고 주장하지 않습니다.

## 1. 할 일·목표 추가

### 재현 순서와 결과

| 순서                                                             | 관찰 결과                                                                             |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 새 임시 프로필로 앱 실행 → 할 일 → 이름 칸을 비운 채 ‘추가’ 클릭 | 목록·저장 자료 0개 유지. 안내·대화상자·입력 칸 오류 표시·입력 칸으로 포커스 이동 없음 |
| 같은 화면에서 이름 칸에 가짜 할 일 제목 입력 → ‘추가’ 클릭       | 실제 JSON에 1개 저장되고 현재 목록에 표시                                             |
| 목표 화면 → 이름 칸을 비운 채 ‘추가’ 클릭                        | 목록·저장 자료 0개 유지. 안내·대화상자·오류 표시 없음                                 |
| 같은 화면에서 이름 칸에 가짜 목표 제목 입력 → ‘추가’ 클릭        | 실제 JSON에 1개 저장되고 현재 목표 카드 표시                                          |

콘솔의 JavaScript 실행 오류는 없었습니다. 따라서 그대로 인용할 오류 메시지도 없습니다. `todoNew`, `projNew` 입력은 `required: false`이고 브라우저 검증 메시지도 빈 문자열이었습니다.

[원본 검사 결과](add-report.json), [빈 할 일 입력에서 추가 후 화면](todos-blank-add.png), [제목 입력 후 생성된 목표 화면](goals-filled-add.png).

### 코드 근거와 판정

[renderer/app.js](../../../renderer/app.js)의 `#todoAdd`, `#projAdd` submit 처리에서 `input.value.trim()`이 빈 값이면 안내 없이 즉시 반환합니다. [renderer/index.html](../../../renderer/index.html)의 추가 버튼은 새 입력 창을 여는 버튼이 아니라, **같은 화면 맨 위의 이름 입력 칸을 제출하는 버튼**입니다.

**빈 이름에서 무반응은 직접 확인했습니다.** 제목을 입력한 뒤 클릭하는 경로는 이 환경에서 정상 저장·표시됐습니다. 사용자가 이름을 입력하지 않았다고 단정하거나, 제목을 입력한 경우의 Windows 문제까지 재현·해결했다고 표시하지 않습니다. 현재 검색·카테고리 필터 등의 조건이 사용자 화면과 같았는지도 확인되지 않았습니다.

## 2. 카테고리 관리

[renderer/styles.css](../../../renderer/styles.css)의 `.cat-edit`는 PC에서 평소 `opacity: 0`이고 해당 행에 마우스를 올리거나 키보드 포커스를 둘 때 나타납니다. 카테고리 이름은 편집 버튼이 아니라 표시 필터입니다.

[renderer/app.js](../../../renderer/app.js)의 `openCatEdit`, `deleteCategory`와 [renderer/index.html](../../../renderer/index.html)의 `#catDialog`, `#cat-delete`에는 이름·색 편집과 삭제 기능이 있습니다. 기본 카테고리와 사용자 카테고리는 편집 대상입니다. ‘미분류’는 카테고리가 없는 항목의 가상 묶음이라 같은 편집 버튼이 없습니다.

따라서 기능이 전혀 없다고 분류하지 않고, **편집 진입 버튼과 삭제 경로가 눈에 잘 드러나지 않는 문제**를 확인 대상으로 둡니다. 이름을 누르거나 더블클릭하면 필터가 바뀌므로 편집·삭제로 오해하기 쉽습니다.

### 실제 Electron 재현 결과

Linux 실제 앱·격리 프로필에서 다음을 확인했습니다. 콘솔 실행 오류는 없었습니다. [검사 결과](category-report.json), [편집·삭제 화면](category-edit-delete.png).

- PC에서 편집 버튼 투명도는 평소 `0`, 행에 마우스를 올리면 `1`입니다. 설정에는 추가 버튼과 왼쪽 연필 사용 안내가 있고 편집 목록은 없습니다.
- 기본 카테고리와 새 카테고리 모두 연필 버튼으로 대화상자를 열어 이름 변경·삭제할 수 있었고, 재로딩 후에도 삭제 상태가 유지됐습니다.
- 새 카테고리는 대화상자의 ‘완료’를 누르기 전에 생성·저장됩니다. ‘추가 → Escape’를 두 번 반복하면 검사 시점의 4개가 6개가 됐습니다. 삭제 버튼은 새 카테고리 대화상자에도 보였습니다.
- 따라서 삭제 기능의 부재와, 관리 진입이 숨겨져 있고 닫아도 새 항목이 남는 동작은 구분해 기록합니다. 이 기록을 사용자 Windows에서 실제로 본 결과로 바꿔 쓰지 않습니다.

## 3. 앱 변경 전 공유할 수정 범위 제안

아래는 아직 적용하지 않은 제안입니다. Claude와 같은 신고 기록을 기준으로 변경 범위와 담당을 맞춘 뒤 기존 앱에서 최소 수정합니다.

| 대상                                             | 바꾸려는 내용                                                                                | 이유                                                                                       |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `renderer/index.html`, 필요 시 `renderer/app.js` | 할 일·목표 이름 입력을 명확히 표시하고, 빈 값에서 추가를 누르면 이름 칸에 포커스와 안내 제공 | 아무 반응 없이 끝나는 동작을 없애고 입력 위치를 알림. 새 입력 창으로 바꿀지는 별도 UI 결정 |
| `renderer/styles.css`, 필요 시 `renderer/app.js` | 카테고리 편집 버튼을 항상 보이고 의미 있는 ‘편집’ 표시와 삭제 경로 안내 제공                 | 숨겨진 연필 아이콘을 찾아야 하는 진입 문제 개선                                            |
| `renderer/app.js`의 신규 카테고리 처리 검토      | 추가 후 완료하지 않고 닫았을 때 새 항목이 남는 동작을 명확히 하거나 생성 취소 방식 검토      | 반복해서 닫는 동안 카테고리만 늘어나는 동작 확인. 변경 방식은 먼저 공유·합의               |
| 추가 회귀 검사                                   | 할 일·목표의 실제 버튼 클릭/빈칸 안내, 기존/신규 카테고리 이름 변경·삭제·재시작 후 유지 검사 | Enter만 확인한 검사로 버튼과 관리 경로의 사용성을 보증하지 않기                            |

현재 이름 입력 후 추가·카테고리 편집/삭제 기능이 있는 사실을 유지하면서 표시와 피드백부터 검토합니다. 사용자 자료를 지우거나 기본 카테고리를 강제로 다시 만들거나, 필터를 임의로 초기화하는 수정은 제안하지 않습니다. 이름을 입력한 뒤에도 실패하는 구체적 조건이 확인되면 그 별도 기록부터 공유합니다.
