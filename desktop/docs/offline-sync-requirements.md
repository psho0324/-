# 오프라인 사용·선택적 계정 동기화·기기 알림 요구사항

확인일: 2026-11-13 (한국 시간). 사용자가 대화에서 정한 다음 개발의 기준입니다. 이 문서는 요구사항과 현재 코드 확인 결과이며, 계정·동기화·모바일 알림의 구현 완료 기록이 아닙니다.

## 기본 사용

- 로그인 없이 시작하고 인터넷·와이파이·모바일 데이터가 없어도 일정, 할 일, 목표, 실천 기록의 작성·수정·삭제·검색·통계와 로컬 백업을 사용합니다.
- 변경은 기기에 먼저 저장합니다. 서버 응답이나 로그인 세션 갱신이 로컬 저장·자료 확인·기기 알림을 막지 않아야 합니다.
- 계정 연결은 선택입니다. 기존 자료를 보존하고, 처음 연결할 때 어느 자료를 해당 계정에 동기화할지 명확히 정합니다.

## 계정 연결 후 자동 동기화

- 같은 계정에 연결한 기기가 인터넷에 접속하면 변경을 자동으로 올리고 받습니다. 정상 동작에 매번 안내창이나 확인을 요구하지 않습니다.
- 연결 실패 중에도 로컬 사용을 유지하고 재시도합니다. 재로그인 등 사용자의 조치가 필요한 상태는 확인할 수 있게 표시합니다.
- 두 기기의 변경·삭제가 겹칠 때 자료가 통째로 덮어써지지 않도록 항목별 변경, 삭제 기록, 충돌 보존과 중복 처리 방식을 먼저 설계합니다.
- 서로 통신할 수 없는 동안 다른 기기의 새 변경을 받을 수는 없습니다. 그동안 각 기기에 저장하고 연결 후 반영합니다.
- 앱이 실행 중이면 연결 복구 시 처리하고, 종료돼 있었다면 다음 실행 때 처리합니다. 모바일 백그라운드 작업은 운영체제가 허용하는 시점에도 수행합니다.

## 오프라인 알림 — 필수

- 기기에 저장된 일정의 알림은 인터넷 없이도 표시해야 합니다. 서버 푸시 수신을 일정 알림의 필수 조건으로 두지 않습니다.
- 처음 로그인하지 않은 사용자도 사용할 수 있어야 합니다. 계정 연결 후에도 알림의 기준은 해당 기기에 저장된 최신 일정입니다.
- 오프라인 상태에서 일정을 추가·수정·삭제하면 그 기기의 알림 예약에도 반영해야 합니다. 나중에 동기화로 받은 변경도 반영합니다.
- 휴대폰에서 화면을 닫은 상태의 알림을 지원하려면 운영체제의 로컬 알림 예약 기능을 사용해야 합니다. 웹 화면의 타이머나 인터넷 푸시만으로 이를 충족했다고 판단하지 않습니다.
- 기기가 꺼져 있거나 운영체제 알림 권한·집중 모드·절전 정책이 표시를 제한하는 상황은 구분합니다. ‘인터넷 불필요’를 ‘기기 전원과 운영체제 상태에 상관없이 반드시 정각 표시’로 설명하지 않습니다.
- 여러 기기에 같은 일정을 동기화했을 때 어느 기기에서 알림을 받을지도 설계합니다. PC와 휴대폰의 알림 사용 설정은 기기별로 유지할 수 있어야 합니다.

## 현재 PC 코드에서 확인한 범위

`desktop/main.js`의 `checkReminders()`는 `desktop/reminders.js`를 통해 로컬 일정과 기기 시각을 확인하고 Electron `Notification`으로 표시합니다. 이 경로에 서버 요청이나 계정 확인이 없습니다. 시작 시와 저장·자료 변경·절전 복귀 때 확인하고, 이후 30초 간격으로도 확인합니다. 실제 표시 성공 기록을 별도 파일에 보관해 재실행 중복을 줄이며 최근 15분의 누락만 제한적으로 처리합니다.

따라서 현재 PC 앱은 앱 또는 트레이 프로세스가 실행 중이면 인터넷 없이 일정 알림을 처리할 수 있는 구조입니다. 알림 클릭은 앱을 엽니다. 실제 Windows의 표시·클릭은 사용자 기기 확인이 필요하며 코드 확인을 실제 표시 검증으로 확대하지 않습니다.

트레이 메뉴에서 완전히 종료한 뒤에는 이 타이머도 종료됩니다. 현재 코드에는 앱 종료 후 운영체제가 대신 실행하는 알림 예약이 없습니다. PC 완전 종료 후 알림을 지원할지는 지원 범위와 별도 운영체제 연동 설계를 정해야 합니다. 휴대폰용 설치 앱과 로컬 알림 예약도 아직 구현하지 않았습니다.

## 구현 전 정할 것과 검증 기준

1. PC는 트레이 실행을 기본 지원 범위로 하고, 앱 프로세스 종료 후 알림이 필요한지 추가로 결정합니다. 휴대폰은 앱 화면이 닫힌 상태의 로컬 알림을 설계에 포함합니다.
2. 네트워크를 실제로 끊고 알림 생성·표시·클릭을 검사합니다. 앱 창을 숨긴 상태, 재실행·재부팅 후 예약 복구도 구분합니다.
3. 일정 시간 변경·반복 회차 수정·삭제 시 이전 알림이 남거나 같은 기기에서 중복 표시되지 않는지 확인합니다.
4. 절전·복귀와 시간대·기기 시각 변경 시 누락된 알림 처리 기준을 정합니다. 운영체제가 허용하는 시간 정확도와 예약 개수 제한은 플랫폼별로 확인합니다.
5. 두 기기 모두 오프라인에서 수정한 뒤 연결하여 자료·삭제·알림 예약이 일치하는지 확인합니다. 서버·인증 장애 중 로컬 사용과 알림이 계속되는지도 검사합니다.

## 작업 및 배포 범위

처음에는 요구사항만 정리했으며 이후 사용자 요청으로 PC 후보 코드를 추가했습니다. 구현 범위와 아직 필요한 실제 서비스 설정은 [0.1.3 개발 후보](v0.1.3-candidate.md)에 구분했습니다. 운영 Supabase·Google 로그인 설정·버전·홈페이지 다운로드 설정은 변경하지 않았습니다.

모든 배포는 사용자가 확인하고 승인한 뒤에만 진행한다. 사용자의 명시적인 “배포해” 승인 전에는 main 병합·버전 올리기·태그 푸시·Release 공개·홈페이지 다운로드 버전 변경을 하지 않습니다.
