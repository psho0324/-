## 이번 작업의 경계

- **문서만 추가했습니다.** 앱의 `main.js`, `preload.js`, `store.js`, `renderer/`와 원본 테스트·의존성·패키징·workflow·Supabase SQL은 변경하지 않았습니다.
- 다운로드 고정 주소와 테스트/미서명 안내는 기존 코드에 있어 유지했습니다. 운영 CMS는 직접 접속 제한으로 현재 별도 다운로드 값의 존재를 확인하지 못했습니다. 저장소 설정·브라우저 검사·공개 Release HTTP 응답과 구분해 기록했습니다.
- Microsoft Learn 웹페이지 접속은 제한되어 Microsoft 공식 공개 문서 원본을 읽었습니다. 인용한 원문 커밋과 공식 페이지 링크를 남겼으며, 실제 신청 화면·심사 결과·추후 요구 변경까지 확인했다고 주장하지 않습니다.
- 코드 서명·Store 제출·모바일 빌드·계정 생성·데이터 이전·동기화를 구현하거나 실행하지 않았고, 새 태그·Release를 만들지 않았습니다.
- 개인 일정·사용자 설정·인증 키를 읽거나 문서에 넣지 않았습니다. 서버 변경 SQL, 운영 비밀 키, 등록용 신분 자료도 포함하지 않았습니다.
- 미확인 설치 앱 수동 항목은 사용자가 진행합니다. 현재 상태와 증거 파일 위치는 [기존 검증 기록](../VERIFICATION.md)에 유지합니다.

## 다음 결정에 도움이 되는 요점

1. 현재 도구에는 AppX 경로가 있고 Microsoft는 Store 제출용 AppX도 받습니다. 최신 상류의 MSIX beta 지원을 현재 고정 버전의 기능으로 혼동하지 않아야 합니다.
2. 홈페이지의 공개 프로젝트와 개인 일정을 같은 자료·권한으로 다루면 안 됩니다. Supabase 프로젝트 재사용 가능 여부와 별개로 소유자별 비공개 저장·명시적 이전·충돌 처리가 필요합니다.
3. 스토어에 설치하는 모바일 앱이라는 방향을 유지하면서 기존 화면 재사용을 우선하면 Capacitor를 먼저 검토할 수 있습니다. PWA는 선택적인 사용성·지원 범위 실험이며, 이번에 모바일 방향을 확정하거나 구현하지 않았습니다.
