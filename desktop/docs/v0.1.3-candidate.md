# 내 플래너 0.1.3 개발 후보

작성일: 2026-11-13 (한국 시간). 다음 PC 버전용 코드 수정안입니다. 사용자의 후속 지시에 따라 모바일 개발은 보류했습니다.

2026-11-16 업데이트: 사용자가 0.1.3으로 업데이트해 다른 PC와 직접 연결을 확인하겠다고 요청했습니다. 이번 배포 승인에 따라 원본 버전을 0.1.3으로 올려 Windows 검사와 공개를 준비합니다. 아래 승인 대기 상태는 개발 당시 기록이며 실제 공개 여부는 GitHub Releases에서 확인합니다. Google 실로그인·기기 간 동기화는 아직 자동 검사 결과에 포함되지 않습니다.

## 버전과 공개 상태

작업 브랜치는 `fix/planner-v0.1.3`입니다. 승인 전 버전 변경 금지 규칙에 따라 package와 잠금 파일의 버전은 **0.1.2**로 유지합니다. 0.1.3이라는 문서·브랜치 이름은 다음 버전의 후보를 뜻합니다. main 병합, 태그, 원격 push, Release, 홈페이지 다운로드 버전 변경은 하지 않았습니다.

모든 배포는 사용자가 확인하고 승인한 뒤에만 진행한다. 검사 결과와 변경 내용을 먼저 보고하고 사용자가 “배포해”라고 명시한 뒤에만 배포합니다.

## 변경한 동작

1. 기존 누락 수정: 업데이트 준비 완료 알림, 트레이의 설치·재시작 메뉴, 시작 실패별 복구 안내, Windows 배치 줄바꿈과 공개 파일 누락 검사를 작업 브랜치에 포함했습니다. 공개 0.1.2에는 이 알림이 없으므로 수정 앱 설치 후의 다음 업데이트부터 새 알림이 동작합니다.
2. 오프라인 일정 알림: 기기 자료와 시각으로 계산합니다. 표시 성공 기록을 별도 파일에 남겨 재실행 중복을 줄이고, 표시 실패는 다시 시도합니다. 24시간을 넘는 사전 알림, 일정 변경·삭제, 시각 변경을 검사합니다. 저장·자료 변경과 절전 복귀 때 재확인하며 정기 확인은 30초 간격입니다.
3. 알림 누락 보완: 최근 15분의 알림만 제한적으로 처리합니다. 한 번에 많으면 최근 개별 2개와 나머지 묶음 1개로 표시해 알림이 계속 쌓이지 않게 합니다. 앱이나 트레이가 완전히 종료돼 있거나 기기가 꺼져 있으면 현재 방식으로는 알림이 나오지 않습니다. OS 알림 권한·집중 모드의 영향도 받습니다.
4. 선택적 계정 연결: 설정에 Google·이메일 인증번호 로그인, 최초 자료 연결 확인, 연결 상태·최근 동기화·대기 건수·로그아웃을 추가했습니다. 로그인 없이 사용을 유지하고 토큰은 native 프로세스에 보관합니다.
5. 자동 동기화: 항목별 변경·삭제 기록, 고정 재시도 번호, 요청·응답 크기 제한, 재시작 후 대기 기록 복구, 다른 기기의 변경 확인을 구현했습니다. 서버 장애와 로그인 만료가 로컬 작성·저장을 막지 않도록 분리했습니다. 정상 동기화는 팝업 없이 반영합니다.
6. 자료 보호: 계정별 캐시와 연결 전 자료를 분리합니다. 계정 전환 중 강제 종료의 애매한 파일은 자동 업로드하지 않고 복구 선택을 제공합니다. 서버의 겹친 수정은 양쪽 사본을 보존하고 최근 사본을 내보낼 수 있습니다. 열린 초안은 다른 곳에서 바뀐 항목을 덮어쓰거나 다른 계정으로 넘어가 저장되지 않게 보호합니다.
7. 패키징·검사: 새 모듈과 공개 설정만 패키지에 포함하도록 검사합니다. 세션·대기 기록·계정 캐시·복구 파일은 Git와 설치 패키지에서 제외합니다. SQL 권한 검사를 별도 CI 작업으로 추가했습니다.

## 삭제·제한한 부분

기존 일정·할 일·목표·카테고리 기능을 삭제하지 않았습니다. 계정 동기화를 사용 중일 때 기존 폴더 파일 동기화를 함께 사용하는 것은 막았습니다. 계정별 자료를 공유 파일로 옮기거나 덮어쓰는 일을 방지하기 위한 제한입니다. 일반 로컬 사용에서는 기존 저장 폴더 선택을 유지합니다.

앱 자체의 자동 업데이트 설치는 기존처럼 저장·백업 확인과 사용자의 설치 동작을 거칩니다. 이번 계정 자료 자동 동기화가 승인 없는 앱 버전 배포를 허용하지 않습니다.

## 실제 연결 전 남은 설정

2026-11-16 사용자가 제공한 플래너 프로젝트의 URL과 publishable 키를 개발용 `account-config.json`에 반영했습니다. 사용자는 SQL 적용·Google 공급자·리디렉션 설정 완료를 알려 주었으며 Google 테스트 사용자 등록 화면을 확인했습니다. 실제 서버 접속·Google 로그인·두 기기 동기화와 인증번호 메일 설정은 아직 검증하지 않았습니다. 현재 공개 설치 앱의 설정은 변경하지 않았습니다. 절차와 연결 확인 범위는 [계정 동기화 연결 준비](account-sync-setup.md)에 정리했습니다. 운영 DB·Google 설정은 사용자가 대시보드에서 직접 변경했으며, 이 작업 환경에서는 실제 메일을 보내거나 계정에 로그인하지 않았습니다.

별도 Windows 계정 테스트 압축 실행본을 만들었습니다. 테스트 표식이 있는 복사본만 기본 자료 폴더와 앱 식별자를 분리하고 자동 업데이트·자동 시작·저장 폴더 변경을 막습니다. 원본 버전은 올리지 않았고 정식 배포 검사는 이 테스트 빌드를 거부합니다. 사용자의 실제 Windows·Google 연결 확인을 위한 파일이며 공개 릴리스가 아닙니다.

## 검증 결과와 한계

검사는 개인 자료 없이 임시 프로필·가짜 계정·로컬 서버로 수행합니다. 실제 결과와 명령은 최종 검토 보고서에 함께 보관합니다.

- 전체 Node 검사: 원본 5개와 업데이트·실행 안전성·테마·반복 목표·공개 파일·동기화·계정·알림·IPC·테스트 빌드 검사까지 총 17개 파일.
- 동기화 SQL 검사: 실제 격리된 PostgreSQL/PGlite에서 사용자 격리, 권한, 동시 수정, 중복 요청, 삭제, 페이지·바이트 제한, 재적용 검증.
- Chromium: 기존 감사·0.1.2 회귀와 새 계정 UI·초안 보호·자료 전환 보호 검사. 인증·파일 IPC는 모의 연결입니다.
- Linux 실제 Electron: 현재 실제 preload·로컬 파일·창·숨김 실행·저장 실패·재실행·기기 백업과 계정 미설정 상태 검사. Windows 결과를 대신하지 않습니다.
- Windows 패키지: 임시 ASAR의 실행 모듈·설정·의존성·개인 자료 제외를 검사합니다. 이 Linux 환경에서 실제 Windows 설치·알림·DPAPI·로그인·기기 간 동기화까지 통과했다고 주장하지 않습니다.

실제 Windows 설치·갱신과 계정 서비스 연결 후의 두 기기 검사가 남아 있습니다. 모바일 앱·계정 삭제 UI·계정 캐시 자동 정리·암호화된 클라우드 종단 간 암호화는 이번 후보에 포함하지 않았습니다.
