## 고정 다운로드 주소

현재 [config.js](../../config.js)의 `desktopReleases.calendar.downloadUrl`은 다음 주소입니다.

```text
https://github.com/psho0324/-/releases/latest/download/MyPlanner-Setup.exe
```

읽기 전용 HTTP HEAD 확인 결과:

| 확인                       | 결과                                            |
| -------------------------- | ----------------------------------------------- |
| 고정 주소의 현재 연결 대상 | `/releases/download/v0.1.0/MyPlanner-Setup.exe` |
| 리다이렉트 후 응답         | HTTP 200                                        |
| 다운로드 파일명            | `MyPlanner-Setup.exe`                           |
| 응답 파일 크기             | 87,478,449 bytes                                |

리다이렉트 중 임시 서명 URL·토큰은 이 문서나 저장소에 기록하지 않습니다.

[앱 package.json](../package.json)의 `artifactName`이 `MyPlanner-Setup.exe`로 고정돼 있고, [Windows 배포 workflow](../../.github/workflows/desktop.yml)는 버전 태그에서 검사를 통과한 파일을 `--latest` Release로 공개합니다. 따라서 다음 정식 Release도 같은 이름의 자산을 포함하면 홈페이지 주소를 유지할 수 있습니다. 비공개·초안·시험 prerelease와 stable latest는 구분해야 합니다.

이 `latest`는 **저장소 전체의 최신 Release**입니다. 앞으로 같은 저장소에 다른 앱의 Release도 만들 경우, 그 Release에 플래너 설치 파일이 없으면 이 주소가 끊길 수 있습니다. 앱별 저장소 분리나 앱별 다운로드 메타데이터 정책은 그때 별도로 결정해야 합니다. 이번에는 저장소·릴리스 구조를 변경하지 않았습니다.

## 코드의 실제 선택 규칙과 확인 한계

[app.js](../../app.js)의 다운로드 창은 **공개 프로젝트가 존재하는 경우에만** 열립니다. 관리자가 등록한 `downloadUrl`이 있으면 그 설정을 우선하고, 없으면 `ready: true`인 위 Release 기본 설정을 사용합니다. 따라서 운영 CMS에 별도 다운로드 주소를 등록하면 그 주소가 우선합니다.

- Release 기본 주소·버전·Windows 지원 환경이 다운로드 버튼에 연결되는 것은 아래 브라우저 검사에서 확인했습니다.
- 별도 관리자 주소를 보존하는 기존 동작도 검사했습니다. 관리자 자료를 임의로 덮어쓰지 않았습니다.
- **공개 홈페이지와 운영 Supabase API의 직접 접속은 이 실행 환경에서 HTTP 403으로 제한됐습니다.** 운영 CMS의 현재 다운로드 필드에 별도 값이 있는지와 사용자 브라우저의 최종 화면은 직접 확인하지 못했습니다. 이는 홈페이지 장애가 관찰됐다는 뜻이 아닙니다.
- 이 확인 기록은 저장소 설정, 재현 가능한 브라우저 검사, 실제 GitHub Release 응답의 확인 결과이며, 운영 사이트 전체를 직접 조작했다고 주장하지 않습니다.

## 테스트 버전·코드 서명 안내

[index.html](../../index.html)의 다운로드 영역에는 다음 안내가 있습니다.

> 이 테스트 버전은 코드 서명이 없어 Windows SmartScreen의 ‘Windows의 PC 보호’ 경고와 ‘알 수 없는 게시자’가 표시될 수 있어요. 이 홈페이지에서 제공하는 MyPlanner-Setup.exe 파일인지 확인하고, 신뢰하는 경우에만 ‘추가 정보 → 실행’을 선택하세요.

현재 공개된 공식 캘린더 Windows 설치 파일 주소에는 이 문구가 표시되며, 준비 중 상태나 다른 앱의 설치 주소에는 잘못 표시하지 않도록 조건이 있습니다. **‘테스트 버전’, ‘코드 서명이 없어’, ‘추가 정보 → 실행’** 문구가 있는 것을 확인했습니다. Store 승인·코드 서명이 완료된 버전으로 표시하지 않습니다.

Edge의 다운로드 보관 확인은 설치 파일을 연 뒤 Windows가 표시하는 ‘추가 정보 → 실행’ 화면과 다른 단계입니다. 이 안내는 보안 경고가 무조건 사라진다거나 파일의 안전성을 OS가 보증한다는 뜻이 아닙니다. 출처를 신뢰하는 파일인지 먼저 확인해야 합니다.
