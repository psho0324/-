# 로그인 후 앱 복귀 보완안 — 2026-11-18 (미배포)

- 실제 Windows 진단에서 백그라운드 콜백의 `show/focus`와 `moveTop` 모두 다른 창의 포커스 잠금을 넘지 못했습니다. 이를 해결됐다고 간주하지 않고 앱 열기 링크를 추가합니다.
- 실제 Chromium의 연속 로그인에서 미리 열린 TCP 연결이 끝난 로그인 시도의 수신기로 새 요청을 전달해 HTTP 400이 되는 문제를 재현했습니다. 종료된 시도의 사용하지 않은 연결을 정리하고, 전송 중인 완료·오류 응답은 끝까지 보냅니다. Host·state·PKCE 검증은 유지합니다.
- 성공 페이지의 ‘플래너로 돌아가기’는 인증 값을 담지 않는 고정 앱 열기 링크입니다. NSIS 설치 파일이 Windows에 프로토콜을 등록합니다. 자동 열기가 차단되면 사용자가 버튼과 브라우저의 ‘열기’ 확인으로 돌아갈 수 있습니다.
- NSIS에서는 사용되지 않는 일반 `protocols` 설정을 제거하고, 실제 설치·삭제 후크에서 링크 등록과 Windows 연결 캐시 알림을 처리합니다. 삭제할 때는 자신의 실행 경로와 일치하는 등록만 지웁니다. 설치 직후 앱을 열기 전에도 등록 경로를 검사합니다.
- 2026-11-20 검토에서 앱 시작 시 별도 HKCU 등록이 모든 사용자 설치의 삭제 후 남을 수 있는 범위 차이를 확인했습니다. 등록은 선택한 설치 범위를 따르는 NSIS에서만 관리하며 앱 시작 시 다른 등록을 덮어쓰지 않습니다. 설치 폴더를 수동으로 이동하거나 연결을 지웠다면 설치 파일로 복구합니다.
- 링크는 앱 창만 열며 인증·동기화를 다시 요청하지 않습니다. 쿼리·fragment·추가 경로·다른 URL·중복 URL을 허용하지 않습니다. 일반 계정 상태 갱신·취소·실패는 앱 창을 움직이지 않습니다.
- 포커스가 거부되면 작업 표시줄에 알리고 실제 포커스를 얻으면 알림을 해제합니다. 앱 열기 확인창을 기다리는 동안 완료 페이지를 유지하며 페이지가 숨겨진 뒤에만 탭 닫기를 시도합니다. 자동 앱 전환·자동 탭 종료를 항상 보장하지 않습니다.
- 버전·잠금 파일·운영 인증 설정·저장 형식·동기화 SQL·홈페이지 다운로드는 변경하지 않습니다. 사용자 승인 전 main 병합·태그·Release 공개를 하지 않습니다.

# 0.1.4 업데이트 준비 — 2026-11-17

로컬의 로그인 실패 안내·로그인 완료 후 앱 복귀 및 탭 정리 개선을 보고한 뒤 사용자가 “반영해봐”라고 지시했습니다. 이번 변경을 0.1.4 업데이트로 준비하며, Windows 설치·업데이트·자료 보존 및 화면 검사 통과 후 공개 여부를 확인합니다. 이후 버전도 사용자 승인 후에만 배포하는 규칙을 유지합니다.

- 오류 콜백의 error/error_code/error_description을 취소·설정/서버 오류·기타 실패의 고정 코드로 바꿉니다. 원문·인증 값은 앱 상태·안내로 전달하지 않습니다.
- 오류 뒤 재시도와 중복·이전 콜백 보호를 검사했습니다. Connection:close로 이전 수신기의 연결 재사용을 방지합니다.
- 성공 페이지는 nonce CSP로 정해진 스크립트만 허용하고 주소의 인증 값을 지운 뒤 탭 닫기를 시도합니다. 닫기가 차단되면 완료 안내를 유지합니다. 성공 후 기존 앱 창을 복원·표시·포커스하도록 연결하며 일반 인증 갱신은 포커스를 바꾸지 않습니다.
- 기존 실패 안내·회귀 검사에 실제 Chromium의 콜백 문서 검사 6개를 추가해 test:renderer에 포함했습니다. 실제 Google·외부 Windows 브라우저 동작을 모의 검사와 구분합니다.
- store.js·동기화 SQL·반복 목표 모델·운영 인증 설정은 수정하지 않습니다. 버전과 잠금 파일을 함께 0.1.4로 맞추며 기존 공개 태그를 유지합니다.
