# 미배포 0.1.1 후보: 추가 버튼·카테고리·버전 표시·자동 업데이트

기준: main `0a73c45`, 현재 공개 앱 `v0.1.0`. 수정 브랜치: `fix/add-button-and-categories`.

Claude가 수정본을 아직 push하지 않았다는 공유 내용을 기준으로 Codex가 기존 코드에서 직접 수정했습니다. Claude의 미전달 파일을 반영했다고 주장하지 않습니다. 이후 자동 업데이트 요청으로 소스 버전만 0.1.1 후보로 올렸습니다. main·태그·Release·홈페이지 다운로드 대상은 변경하지 않았습니다.

## 원인과 변경

- 할 일/목표 추가는 제목이 빈 경우 안내 없이 반환했습니다. 제목 입력 위치를 표시하고, 빈칸·공백에서 안내와 포커스를 제공합니다. 실제 추가 버튼 클릭으로 생성·표시·저장을 검사합니다. 사용자가 Windows에서 제목을 입력한 뒤에도 겪었을 수 있는 모든 무반응 조건을 재현했다고 단정하지 않습니다.
- PC 카테고리 편집 아이콘은 평소 숨겨졌습니다. 사이드바에 ‘편집’을 항상 표시하고 설정에 기존 카테고리의 ‘편집·삭제’ 진입 목록을 제공합니다.
- 새 카테고리는 창을 열 때 즉시 저장됐습니다. 새 항목은 초안으로 보관하고 ‘추가’를 눌러야 저장합니다. 취소·Esc·종료로는 생성되지 않습니다. 기존 카테고리의 이름·색 즉시 적용과 삭제·실행 취소 의미는 유지합니다.

## 2026-11-11: 현재 버전 표시 추가

사용자 요청에 따라 설정의 ‘앱 정보 → 현재 버전’과 창 제목에 실행 중인 앱 버전을 표시합니다. main의 `app.getVersion()`을 고정된 `app:version` IPC와 preload의 `plannerApp.getVersion()`으로 읽습니다. 화면에 버전을 하드코딩하거나 사용자 일정 JSON에서 읽지 않습니다. 브라우저 미리보기는 ‘브라우저 미리보기’, 조회 실패는 확인 불가 안내로 구분합니다.

이 버전 표시 변경 당시 package는 0.1.0이었습니다. 이후 아래 자동 업데이트 준비에서 소스 버전을 0.1.1로 변경했습니다. 공개 앱은 아직 0.1.0입니다.

## 수정 파일

- `main.js`, `preload.js`: 실제 앱 버전만 읽는 고정 IPC와 제한된 화면 API 추가.
- `renderer/index.html`: 입력 이름·오류 안내, 명확한 추가 버튼 문구, 설정 관리 목록, 새 카테고리 취소 버튼, 앱 버전 표시 영역.
- `renderer/app.js`: 빈 제목 피드백, 편집 진입, 신규 카테고리의 확정 전 저장 차단·확정 처리, 실행 중 버전 조회와 표시.
- `renderer/styles.css`: 오류·관리 목록 표시와 편집 버튼 상시 노출.
- `tools/desktop-smoke.cjs`: 실제 Electron의 소스·설치 앱에서 같은 회귀 시나리오를 실행하도록 검사 추가.
- `tools/browser-tests/smoke2.js`: 새 카테고리 확정/취소 의미에 맞춘 검사. 설치된 Chromium과 로컬 HTTP 미리보기를 선택할 수 있게 환경 변수 지원.
- `tools/browser-tests/build-preview.js`: HTTP 검사에서 한글이 깨지지 않도록 테스트 미리보기에 UTF-8 선언 추가. 테스트 HTTP 서버의 불필요한 favicon 404를 막도록 빈 아이콘 지정. 실제 앱 HTML은 이미 UTF-8 선언이 있었습니다.

## 검사와 범위

- 원본 Node 테스트 5개 파일: 통과.
- Linux 실제 Electron: 11개 검사 그룹 통과(실제 버전 IPC·package 메타데이터·설정 표시·창 제목 일치 포함). 실제 버튼 클릭/빈칸 안내, 새 카테고리 이름·색 입력 후 취소·Esc·재로딩, 설정에서 이름 변경·추가·삭제·실행 취소, 연결된 할 일·목표 보존, 즉시 종료 후 복원, 백업, 단일 실행, 저장 실패/재시도, 숨김 시작 포함.
- 기존 화면 회귀 검사: 175/175 통과(브라우저 미리보기 버전 구분 포함)(390px 포함, 콘솔·페이지 오류 없음).
- Windows PR 자동 검사: PR 생성 후 실행 여부와 결과를 따로 확인해야 합니다. 이번 Linux 결과를 Windows 설치 앱 결과로 확대하지 않습니다.
- 실제 사용자 일정·백업·인증 키는 사용하지 않았습니다. 검사에는 격리된 임시 프로필과 가짜 자료만 사용했습니다.

## 검사 도중 확인한 도구 문제

앱의 카테고리 이름은 기존부터 최대 20자입니다. 처음 추가한 회귀 검사 자료가 20자를 넘어 기대 문자열과 달라 `Existing category rename not saved`가 발생했습니다. 이 실패는 앱 수정 원인으로 삼지 않았으며 검사 자료를 제한 안의 이름으로 바꿨습니다.

별도 Chromium 검사는 이 실행 환경의 file URL 제한으로 `ERR_BLOCKED_BY_ADMINISTRATOR`를 반환했습니다. 허용된 로컬 HTTP를 사용했으며, 테스트 미리보기의 UTF-8 선언 누락 때문에 나타난 한글 깨짐은 미리보기 생성 도구에서 수정했습니다. 실제 Electron 검사에서는 변경하지 않은 앱 CSP와 실제 preload/파일 IPC를 사용합니다.

## 2026-11-11: 자동 업데이트 준비

Claude의 사용량 소진 이후 요청을 이어받았습니다. main/preload/화면 수정 목적을 먼저 설명한 뒤 구현했습니다.

- `electron-updater` 6.8.11 및 `updater.js`: 설치된 Windows NSIS 앱에서 자동 확인·다운로드. 설치는 사용자 버튼으로만 진행합니다.
- `main.js`: 화면의 저장 완료를 명시적으로 확인하고 로컬 백업 후 설치·재실행합니다. 저장 응답 없음, 저장/백업 실패에는 설치를 막습니다. 기존 일반 종료 처리는 유지합니다.
- `preload.js`: 상태 조회·확인·설치·상태 구독만 고정 IPC로 노출합니다.
- `renderer/app.js`, `renderer/index.html`: 설정에 진행 상태·설치 버튼과 메뉴 알림 표시. 개발 실행·브라우저·Store는 구분합니다.
- Windows 워크플로: 업데이트 메타데이터 공개와 실제 다음 버전 갱신 검사를 추가했습니다. 버전은 0.1.1 후보로 준비했으며 배포하지 않았습니다.
- 현재 검사: Node 7개 파일(업데이트 제어 18개·실제 라이브러리 다운로드 3개 포함), Linux 실제 Electron 12개 그룹, 화면 176개 통과. Windows NSIS 설치·실제 업데이트 결과는 대기 중입니다.
- Linux에서 Windows NSIS 빌드는 `spawn wine ENOENT`로 중단됐습니다. 설치 파일이 완성됐다고 판단하지 않습니다. 처음 추가한 Electron 검사 도구의 `require is not defined`는 평가 컨텍스트 문제였으며 도구를 고친 뒤 12개 그룹이 통과했습니다.

설계·검증 한계·첫 수동 설치 절차는 [자동 업데이트 문서](docs/auto-update.md)에 기록했습니다. `store.js`와 사용자 데이터 형식은 변경하지 않았습니다.
