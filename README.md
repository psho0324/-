# 떠돌이의 작업실

앱·제작 기록·다음 실험을 공개하고, 본인 계정으로 관리하는 개인 작업실입니다.

## 현재 운영 방식

- **사이트 코드**는 GitHub에서 관리합니다.
- **프로젝트·기록·아이디어·초안·수정 이력**은 Supabase에 저장합니다.
- **업로드 이미지**는 Supabase의 비공개 `workspace-media` 버킷에 보관합니다. 관리자와 공개된 항목에 연결된 이미지에만 접근을 허용합니다.
- `projects.js`와 `journal.js`는 최초 예시와 미연결 화면용입니다. 운영 중 내용을 바꾸려면 관리자 화면을 사용합니다. 이 파일을 바꿔도 운영 DB의 자료가 수정되지 않습니다.

## 설치·실행·검증

Node.js 22 이상과 Python 3을 사용합니다. 앱의 정적 실행 자체에는 npm 설치가 필요하지 않습니다.

```sh
npm ci
npm start
```

개발 검증:

```sh
npx playwright install chromium
npm test
npm run build
```

시스템 Chromium을 사용한다면 `CHROMIUM_EXECUTABLE=/usr/bin/chromium npm test`로 실행합니다. 빌드 결과는 `dist/`입니다. 빌드는 파일 버전 주소를 갱신합니다.

기존 클라우드 체크아웃을 그대로 사용합니다. 각 클라우드 작업은 이미 격리되어 있으므로 별도의 Git worktree를 만들 필요가 없습니다.

## 처음 설정하거나 기존 사이트 확장하기

[SETUP.md](SETUP.md)를 따릅니다. 기존 사이트는 Supabase SQL Editor에서 `supabase/migrations/002_workspace.sql`을 한 번 실행하면 됩니다. 기존 프로젝트·기록은 자동으로 보존·이관되며 관리자 계정은 그대로 사용합니다. 실행 전 Supabase에서 기존 테이블을 내보내 보관할 수 있습니다.

## 저장·공개·복원

- 새 프로젝트는 이름과 간단한 소개만으로 초안 저장할 수 있습니다.
- 공개된 항목을 수정 초안으로 저장해도 기존 공개본은 유지됩니다.
- 공개 중지는 별도 버튼으로 수행합니다. 초안 저장과 구분합니다.
- 다른 탭에서 먼저 수정한 경우 저장을 거부하고 현재 입력은 유지합니다. 최신 내용을 확인하거나 작성 중 내용을 새 초안으로 복사할 수 있습니다.
- 저장 요청에 고유 번호를 붙여 응답 유실 후 재시도도 한 번만 처리합니다.
- 저장하지 않은 입력은 관리자별로 이 브라우저에 임시 보관하며 다음 로그인 때 이어 쓸 수 있습니다. 다른 기기에 자동으로 옮겨지는 것은 아닙니다. 공유 컴퓨터에서는 사용 후 임시 내용을 지워 주세요.
- 삭제는 휴지통 이동입니다. 복원은 비공개 초안으로 수행합니다. 이력에서 이전 내용을 수정 초안으로 되돌릴 수도 있습니다.

## 이미지·백업

PNG/JPG/WEBP/GIF 파일을 장당 5MB 이하로 업로드합니다. 기록에는 최대 10장을 첨부합니다. 외부 HTTPS 이미지 주소도 사용할 수 있습니다.

‘백업·복원’에서 내용·초안·휴지통·수정 이력과 업로드한 이미지가 포함된 JSON 파일을 내려받습니다. 외부 URL 이미지의 원본 파일은 포함하지 않습니다. 파일에는 비공개 초안이 포함되므로 안전하게 보관하세요.

복원은 현재 내용을 덮어쓰지 않고 휴지통을 제외한 내용을 새 초안으로 추가합니다. 프로젝트와 기록의 연결도 새 ID로 다시 연결합니다. 백업의 과거 이력은 파일에서 보관되며 복원본 이력은 새로 시작합니다. 기존 휴지통·이력을 그대로 유지하려면 Supabase의 데이터베이스 백업·복원도 별도로 사용해야 합니다. 내보내기 기능이 서버의 자동 정기 백업을 대신하는 것은 아닙니다.

## 공개 페이지·자동화

공개 목록은 페이지 단위로 불러오고, 기록 본문은 펼칠 때 불러옵니다. 각 영역의 오류는 독립적으로 처리합니다. 프로젝트 ID `all`도 전체 필터와 충돌하지 않습니다.

‘소개 보기’는 앱 실행과 별개이며, 프로젝트 공유 주소를 복사할 수 있습니다. `WORKSPACE_SNAPSHOT=1 npm run build`는 공개된 프로젝트만 읽어 `dist/projects/<id>/index.html`, 공유 메타데이터와 사이트맵을 만듭니다. GitHub Pages에서 이런 페이지를 배포하려면 [SETUP.md](SETUP.md)의 GitHub Actions 전환 단계를 완료하세요. 새 프로젝트 링크는 스냅샷 전에도 404 페이지에서 최신 API 화면으로 연결됩니다.

GitHub Actions는 푸시와 PR에서 테스트·빌드를 실행합니다. Pages 배포 워크플로는 main 변경과 6시간 간격, 수동 실행을 지원합니다. 관리자에서 저장한 최신 내용은 새로고침으로 바로 읽으며 검색·공유용 정적 소개 페이지는 다음 빌드 때 갱신됩니다. 검색 서비스나 메신저 자체의 캐시 갱신 시점까지 보장하지는 않습니다.

## 테스트 범위

- `tests/database.test.cjs`: 기존 DB 정책
- `tests/workspace.test.cjs`: 새 저장 함수·권한·이미지 정책·이관·중복 방지·버전 충돌·휴지통·이력·백업 복원
- `tests/browser.test.cjs`: 실제 로컬 PostgreSQL 함수에 연결한 Chromium 통합 검증. Supabase의 인증 HTTP와 파일 전송만 모의 처리하며 실제 서비스에 메일·데이터를 보내지 않습니다.
- `tests/build.test.cjs`: 공개 데이터만 사용한 정적 페이지·메타데이터 생성과 텍스트 이스케이프

운영 Supabase의 실제 설정과 GitHub Actions 최초 실행은 각 서비스에서 확인해야 합니다. 클라우드 환경의 네트워크 허용 정책은 브라우저 방문자의 네트워크와 별개입니다.

## 다운로드 창

프로젝트 카드의 ‘다운로드’ 또는 소개 창의 ‘다운로드 안내’에서 PC 다운로드와 모바일 준비 상태를 확인합니다. 설치 파일이나 다운로드 페이지 URL이 없으면 비활성화된 준비 중 안내를 표시합니다. 기존 ‘앱 주소’를 설치 파일 주소로 간주하지 않습니다.

관리자의 프로젝트 편집 → ‘다운로드 창 설정’에서 PC 운영체제, HTTPS 다운로드 주소, 버전, 지원 환경, 모바일 준비 여부를 입력합니다. 버전과 지원 환경을 입력하지 않으면 임의의 값을 표시하지 않습니다. 이 정보는 기존 JSON 저장 구조에 포함되므로 새 SQL 실행은 필요하지 않습니다. 기존 확장 설정 SQL은 먼저 적용되어 있어야 관리자 저장 기능을 사용할 수 있습니다.

설치 파일을 실제로 빌드하거나 배포하는 기능은 포함하지 않습니다. GitHub Releases 등에서 공개한 파일 주소를 등록해 사용할 수 있습니다.
